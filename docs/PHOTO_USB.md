## NEXT — SLDN, после ПИН

Числа команд десятичные. Полный кадр: `SLDN`, длина UInt16 LE, тело,
CRC16 (A001/FFFF) по длине и телу. Тело запроса `[255, id, команда, данные]`,
ответа `[60, id, команда, данные]`. Многобайтные поля LE.

| Команда | Данные / ответ | Эталон |
|---|---|---|
| 7 — снимок | Запрос: адрес камеры UInt8. Ответ 11: исходная команда UInt8, код UInt8, время UInt32, свободный буфер UInt16 | User/user_fun.c:2984–2985, :1872–1907; User/photo.c:129–174 |
| 21 — запрос фото | Без данных либо номер UInt32 + смещение UInt16. 0/0 — первое неподтверждённое место; смещение=размер подтверждает фото. Ответ 11: 0 успех, 1 неверный курсор (повтор 0/0), 2 занято, 4 нужен ПИН | User/user_fun.c:3470–3475; User/photo.c:495–547 |
| 14 — поток | Счётчик UInt8, номер UInt32, размер UInt32, смещение UInt16, до 512 байт JPEG. Пустая очередь: один байт 0 | User/photo.c:549–593 |
| 101 — состояние | Полный кадр 42 байта; флаги UInt16 по смещению 13; бит 11 запрещает обе фото-операции | User/user_fun.c:2041–2078; structures.h:213 |

Логика сопоставлена с `Tools/Photo/photo_server_gui.py:70–196`.
Приём сохраняет `.partial` с Flush(true) перед подтверждением, сверяет повторы,
повторяет запрос при пропуске/таймауте. Подтверждённое начало требуется в той же
папке; если оно отсутствует, операция останавливается с объяснением.
JPEG проверяется по FFD8/FFD9 и декодированием. Другой существующий JPEG
не перезаписывается. После завершения сохраняется `<IMEI>_<номер>.jpg`.
Во время приёма обычный опрос уступает порт PhotoSession, который сам читает
статус. Выход из окна отменяет операцию перед освобождением порта.
Для съёмки проверяются прочитанные настройки: RS-485 активен и есть C328 (тип 3).
Выгрузка уже накопленной очереди возможна без настроенной камеры.

## v5 — SLGT

| Команда | Реальное поведение v5 | Эталон |
|---|---|---|
| 0x30 | Всегда тело ответа `[55, 30, FA]` — функция не реализована | User/user_fun.c:752–756 |
| 0x31 | Нет обработчика/ответа | User/user_fun.c:757–758 |
| 0x32 | Нет обработчика/ответа | User/user_fun.c:759 |

Старый конфигуратор `Unit1.cpp:1328–1380` содержит другую, отсутствующую в
этой v5 схему: ответ 0x30 типа 0 сообщает размер UInt24 LE, типа 1 — длину
UInt16 LE и данные; продолжение запрашивается 0x30 с `[1,0]`; типы 2/3 —
занято/нет камеры. Она не включена в NextConfig. 0x31/0x32 для этой схемы
не нужны. В допуск SLGT добавлены только разрешённые 0x30/0x31/0x32;
экран сообщает об отсутствии поддержки, эти бесполезные запросы не отправляет.
`gchrono` и журнал старой платы не реализовывались.

## Проверки

`tests/photo-read.ps1`: поток с потерей и повтором, две фотографии, полное
подтверждение/пустая очередь, снимок и следующая выгрузка, продолжение из
.partial, конфликт повторного пакета, защита файла, неправильный JPEG,
потерянное подтверждённое начало, блокировка обновлением до отправки 7/21,
отказ камеры, CRC/фрагментация/несколько кадров, отсутствие фото в v5.
Демо: `--demo-photo=loss` (по умолчанию), `empty`, `bad-jpeg`, `missing-prefix`,
`updating`, `no-camera`. Для воспроизводимой проверки выбора папки можно
передать `--demo-photo-folder=<существующая папка>`; диалог всё равно открывается.
Реальные камера, плата, питание/обрыв USB и поведение CH_USB требуют проверки
с владельцем. Снимки и результаты лежат вне git в `Стенд_Domovoi/NextConfig_QA`.
