# Старая прошивка Domovoi: этап 1, только чтение

Запуск: `NextConfig\bin\Release\NextConfig.exe --demo:oldfw48`.
Обычный запуск сохраняет поиск NEXT и загрузчиков; после ответа старого приложения
открывается отдельный единый экран чтения. Закрытие экрана завершает сеанс,
не запускает повторный поиск и не предлагает перепрошивку.

В демо `SerialPort.Open` не вызывается. Идентификаторы, номера и имя сервера вымышлены.
Демо возвращает байтовые ответы в общий парсер, а не заполняет поля формы напрямую.

## Эталоны и обозначения

Все пути ниже относительно `СофтЭксперт/От старой системы/Финальный релиз только v5`:

- **FW**: `Naviset Domovoi(Mini)_v3.0_IAR93/Naviset Domovoi(Mini)_v3.0_IAR93`.
- **CFG**: `Configurator Domovoi Mini/Configurator Domovoi Mini`.
- Исходники читаются как CP1251. Прошивка и старый конфигуратор не изменялись.
- `P` — данные ответа после `[55, команда]`; `D` — начало вложенной структуры.
- Многобайтные числа — little endian, строки — CP1251 до первого нуля.
- Общий кадр: `SLGT`, `UInt16 длина тела`, тело, `CRC16 тела`.
  CRC16: init `FFFF`, полином `A001`, младший байт первым. Используется `clBoot.Frame/Exchange`.

## Команды

| Команда | Данные запроса | Ответ / раскладка | Доступ и источник |
|---|---|---|---|
| `00` | нет | Приложение: 24 байта `P`: `[0]=1`, `[1]=BOOT_VER`, `[2]=BOOTHW_VER`, `[3]=FW`, `[4]=DEVICETYPE`, `[5]=BOOT_RESTRICT`, `[6..7]=резерв`, `[8..23]=IMEI[16]`. Полное тело 26 байт. Отдельного серийного номера нет. | Без пароля. FW `User/user_fun.c:4806–4819`; CFG `Unit1.cpp:837–881`. |
| `00`, загрузчик | нет | 8 байт `P`: `[0]=0`, далее версия загрузчика, HW загрузчика, FW приложения, HW приложения, ограничение, два резервных байта. Полное тело 10 байт. | FW `Bootloader/bootloader.c:341–350`. Отличие от приложения — признак и длина, **не** версия `<30`. |
| `22` | `[0]` — блок 0 | `P[0]=блок`, `UInt16(P+1)=размер`, `D=P+3`: packed `DEVICE`. В данных исходниках **513 байт**, вопреки комментарию «512». | Без пароля. FW `User/user_fun.c:476–483`, `structures.h:79–262`; CFG `Unit1.cpp:1038–1048`, `Unit1.h:768–919`. |
| `20` | `[0]` — блок 0 | `P[0]=статус`, `[1]=блок`, `UInt16(P+2)=512`, `D=P+4`: `ConfStr[512]`. | Администратор. FW `User/user_fun.c:421–438`, `structures.h:336–407`; CFG `Unit1.cpp:966–981`, `Unit1.h:995–1057`. |
| `25` | пароль `UInt16`, ввод владельца | `[статус, уровень]`. Успех `0`, неверный пароль `3`. Уровни: `00` нет, `10` управляющий, `20` администратор, `40` IP-пользователь. На защищённое чтение вместо его ответа может прийти `25: [4, текущий уровень, требуемый]`, где требуемый `2` — администратор, `1` — управляющий. | FW `User/user_fun.c:346–374,495–515`, `structures.h:17–20`; CFG `Unit1.cpp:1060–1069`. Встроенных паролей и расчёта универсального пароля нет. |
| `2C`, количество | `[0]` | `[0, количество UInt16]`. | Минимум управляющий. FW `User/user_fun.c:626–639`; CFG `Unit1.cpp:1154–1181`. |
| `2C`, блок | `[1, индекс UInt16]` | `[1, индекс UInt16, количество UInt16, записи по 64 байта]`. USB — до 31 записи в одном блоке (полное тело до 1991 байта). Проверяются индекс, длина, ненулевой прогресс и граница общего количества. | FW `User/user_fun.c:641–669`, `structures.h:266–287`; CFG `Unit1.cpp:1182–1198,3739–3747`, `Unit1.h:945–972`. |
| `2E` | **не отправляется** | В v5 обработчик пуст. | FW `User/user_fun.c:741–742`. В CFG есть старый приём количества/32-байтовых записей (`Unit1.cpp:1256–1301`), но прошивка на запрос не отвечает. |
| `40` | **не отправляется** | Это отправка SMS со статусом; с `USE_UPDATEGSMFW` — вход в обновление модема. Не чтение журнала. В обратном направлении CFG умеет показать входящий `logs_t[32]`. | FW `User/user_fun.c:764–821`; CFG `Unit1.cpp:1518–1524`. |
| `41` | **не отправляется** | Подтверждение получения серверного лога, меняет состояние его доставки. | FW `User/user_fun.c:824–826`. |

Список допуска нового транспорта: **00, 20, 22, 25, 2C**. Другие команды,
включая 2E/40/41, отклоняются до обращения к порту. Уже существующие функции
записи NEXT/загрузчика сохранены, но на экране старой прошивки недоступны.
Обмен последовательный; мониторинг не вклинивается между блоками базы.
Закрытие прерывает чтение перед следующим пакетом; текущий обмен имеет таймаут 3 с.

**Особенность самой прошивки:** любой корректный пакет устанавливает флаг
подключения конфигуратора (`user_fun.c:400–401`); `2C/0` дополнительно записывает
событие чтения базы в журнал (`:638`). Настройки и база командами этого этапа не меняются.

## Полезные смещения структур

### Настройки (D, 512 байт)

| Смещение | Поля |
|---|---|
| 0–4 | идентификатор, версия, номер/количество конфигураций, оборудование |
| 5, 9, 11 | время изменения UInt32, пароль администратора UInt16, пароль управляющего UInt16 |
| 13 | биты: все вызовы, NTP, вход 1, вход 2, фото, пароль, перезапуск, выход по периоду |
| 14, 15, 55 | оператор; APN[40]; PIN SIM[5] |
| 60–91 | `connectstr`: флаги, протокол, время активности UInt16, таймаут UInt16, адрес[24], порт UInt16 |
| 92, 116, 118 | NTP[24], порт NTP UInt16, номер SIM[16] |
| 134–137 | тип выхода, импульс, пауза, повторы |
| 138–158 | 7 расписаний: маска дней, час начала, час конца |
| 159–163 | разрешение фото; знаковый часовой пояс; час перезапуска; начало/конец периода выхода |
| 164 | GNSS, тип выхода по времени, SMS незарегистрированным, баланс, пересылка SMS, 3 резервных бита |
| 165–171 | минуты начала/конца, дни, гудки, функции двух входов, задержка фото |
| 172, 174, 176 | порог баланса UInt16, числовой код запроса UInt16, строка запроса[16] |
| 192–194 | расписание приёма всех вызовов, число RFID-антенн, тип считывателя |
| 195–509, 510–511 | резерв[315] и CRC конфигурации |

Поля подписаны по-русски и доступны в одной таблице с поиском по разделу/названию.
Пароли/PIN скрыты до включения флажка. Резерв и CRC отображаются в hex.
CRC кадра проверяется транспортом; CRC вложенной конфигурации только отображается.

### Мониторинг

IMEI D+0[16]; FW +16; HW +17; коды сборки +18/+20; заказчик +22;
GSM/GPRS — полубайты +23; CSQ +24; флаги подключения +32;
номер вызова +33[16]; наработка UInt32 +49; оператор +53;
количество номеров UInt16 +54; доступ +60; температура int8 +61;
АЦП UInt16 +62/+64; местное время UInt32 +66; входы/выход/достоверность времени +70;
счётчик журнала UInt16 +79; лимит номеров +160; баланс +166;
RFID-считыватели +237; маска антенн +238; сеть +269; питание, мВ UInt16 +270.
Исходный DEVICE сохраняется в строке просмотра целиком. Служебные адреса/таймеры
в конце структуры не интерпретируются как пользовательские настройки.

### Запись номера / ID (64 байта)

Метка +0; номер/ID как строка +1[11]; имя CP1251 +12[20];
флаги +32: доступ bits0–1, изменён bit2, новый bit3, тип bits4–5;
срок действия UInt32 +33; лимит проходов +37; расписание +38;
использованные проходы +39; резерв +40[24]. Типы: телефон, 1-Wire, RFID, неизвестный.
Все 64 исходных байта дополнительно включены в CSV.

CSV: UTF-8 с BOM, разделитель `;`, экранирование кавычек и переносов строк.
Нули в начале ID сохранены **в файле**; при импорте в Excel столбец номера/ID
следует выбирать как текстовый. Строки, похожие на формулы, получают префикс `'`;
оригинал всегда восстановим из колонки с 64 байтами. Экспорт доступен только после
полного успешного чтения, в том числе для пустой базы. Неполный результат не выдаётся
за полный; после ошибки повторного чтения старый экспорт отключён.

## Журнал старого конфигуратора

Согласованное ограничение на экране: «Чтение журнала не поддерживается этой прошивкой».
Локальный запрос CFG — только `2E` (`Unit1.cpp:3854–3865,3911–3918`).
Есть **другой источник**: внешний сервер (`:3901–3907`), функция
`GetChronoFromServer` (`:5396–5414`) отправляет JSON с IMEI, паролем, командой
`gchrono`, датами, номером и фильтром операции через `SendHttpRequest`.
Также CFG отображает входящие 32-байтовые события `40` (`:1518–1524`).
Ни серверный запрос, ни приём серверного потока в этот этап не добавлены;
для отдельного этапа требуется решение владельца. Внешние сервисы не вызывались.

## v1–v3: только сравнение

В исходниках `Старый релиз для v1-v3/v1-v3/Naviset Domovoi(Mini)_IAR75`
кадр и форматы рассматриваемых ответов совпадают; проверенные смещения ConfStr,
DEVICE и phoneparams_t также совпадают. Некоторые DIN-варианты имеют тот же
DEVICETYPE `8B` (`board.h:17`), поэтому это **не доказательство ревизии платы**.

Существенное различие поведения `2C`: в v1–v3 `User/user_fun.c:619–624` собирает
ответ количества до `user_getnumberscount`, а `:643–650` отправляет запрошенное
количество, игнорируя фактический результат `user_readnumbers`. v5 формирует
количество после пересчёта и использует возвращённое число прочитанных записей.
`2E` в v1–v3 также закомментирована (`:727` и далее).
Поддержка v1–v3 не реализовывалась и не заявляется.

## Вопросы владельцу перед проверкой на железе

1. Уточнить физическую ревизию платы: тип `8B` не отличает все старые DIN-варианты.
2. Нужны ли привычные названия для кодов оператора, функций входов, типа выхода,
   разрешения фото и считывателя? Сейчас неоднозначные значения показаны как исходные
   коды, единицы для некоторых таймаутов/задержек не выдуманы.
3. Есть ли известные значения BOOT_RESTRICT, кроме трактовки старого CFG
   `10h → 650 номеров`, иначе `15000` (`Unit1.cpp:844–847`)? Показывается исходный код.
4. Серверный журнал `gchrono` — отдельное поручение; доступ и пароль не сохраняются в коде.
